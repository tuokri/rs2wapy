# Fixtures

`capture/` is generated by `tools/probe_webadmin.py`. `policy-roundtrip/` is a
separate capture set that records the add/delete restoration test.
`player-actions/` is generated by `tools/player_action_probe.py` and records a
controlled mute/unmute, session-ban/revoke, and optional ID-ban/revoke
sequence. `kick-ban-actions/` is generated by `tools/kick_ban_probe.py` and
records reconnect-confirmed kick and permanent-ID-ban/revoke lifecycles. Each
capture set has:

`multiadmin-sha1/` records the empty-server MultiAdmin/SHA-1 read surface.
`multiadmin-sha1-authz/` records accepted SHA-1 and plaintext login forms,
remembered-session behavior, selected administrator profiles, a full secondary
administrator read matrix, and disabled-account login denial.
`multiadmin-readonly/` records authentication boundaries, session isolation,
route error shape, and `/data` selector responses.
`multiadmin-permissions/` records a temporary enable/read/deny/disable cycle
for the disposable restricted account, including verified restoration.
`multiadmin-empty-state/` records all current game-type refresh fragments,
empty-game-type behavior, safe update-form refreshes, sorting, `/data` POST
parity, and empty chat polls.
`phase3-core/` records notes save/readback/restoration, no-output console
submissions, and a synthetic short-lived ID-ban add/revoke restoration cycle.
`phase3-travel-roundtrip/` records an empty-server alternate-map travel and
exact baseline restoration, including each transient readiness poll.
`phase3-policy-validation-roundtrip/` records inline policy validation errors,
duplicate/add/update/delete behavior, and verified restoration of the original
policy count.
`phase3-welcome-settings/` records a welcome MOTD save/readback/restore and
the submitted browser-compatible welcome-toggle fields.
`phase3-console-log/` records harmless console submissions whose empty page
output was independently correlated with the server log outside this fixture

- `index.json`: sanitized capture metadata, status, response headers, and file
  names
- `*.html` or `*.txt`: normalized response body
- `*.request.json`: normalized method, path, headers, and form field names

The fixture set intentionally contains no passwords, password hashes, cookie
values, form tokens, stable player identifiers, player names, administrator
IDs, administrator display names, IP addresses, timestamps, or server address.
The probe assigns stable aliases such as `{{PLAYER_1}}`, `{{ADMIN_1}}`, and
`{{IP_ADDRESS_1}}` for the duration of one capture run so relationships remain
testable without exposing source values. Regenerate captures against the
authorized development server when WebAdmin changes.
